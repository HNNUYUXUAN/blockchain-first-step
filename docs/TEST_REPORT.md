## 后端 11 项

1. 连接实际 EVM；部署前拒绝记录
2. 多次同时部署只产生一个合约；校验已部署 runtime 字节码与成功回执
3. UTF-8 原样 SHA-256，实际写入、回读、交易/区块哈希核对；不保留原文
4. 篡改、尾部空格、Unicode 规范化差异均可检出
5. 1,000 个 Unicode 码点边界、非法类型、空白、超大请求与非法编码
6. 12 个并发相同写入请求合并；重复重试相同回执；同 key 不同内容被拒绝
7. 合约直接调用允许其他账户追加，不允许覆盖已有 ID
8. 同源/本机 Host 边界，跨站写入与 DNS rebinding 被拒绝
9. 真实停止和重启节点；旧合约索引与幂等请求清空
10. npm start 启动页面/节点，静态文件正常，退出时两服务关闭
11. 错误教学链 ID 被拒绝

## DOM + 真链 11 个检查点

页面 JavaScript 在 jsdom 中执行，fetch 连接实际启动的本地 API，API 调用真实 EVM；未伪造交易回执。

1. 初始写入禁用、账户来自节点、没有伪造回执
2. SHA-256 计算不会产生交易
3. 部署成功更新页面状态与回执
4. 空白与过长输入不发交易
5. 双击及同一请求重试只生成一笔真实写交易
6. 原文回读一致，并显示“不能证明内容真实”
7. 改一个字使旧结果立即失效，重新回读不一致
8. 真实停链后取消成功验证，禁用写入
9. 新链连接后清除旧回执、合约和请求
10. 新链重新部署、写入、回读验证成功
11. HTML 字符串以纯文本处理，没有插入危险元素

独立审阅发现的“断链后旧验证结果残留”问题已修复，上述 8–10 项为对应实际回归。

在有 Chromium 的 Ubuntu/WSL2 环境中可执行：

```bash
npm ci
npx playwright install chromium   # 已有可用Chromium可省略
npm run test:ui
npm test
```

默认优先 `/usr/bin/chromium`，也可显式传 `CHROMIUM_PATH`。运行后 `evidence/` 将生成真实截图与 UI 结果。请先完成这一阶段，再宣称视觉与浏览器兼容性已验证。
